# Safety and Scope

JanusGuard is a **defensive, educational, static analysis** tool. This document
states clearly what the tool does and does not do, so that anyone reading the
repository, running the tool, or grading the project can verify our scope.

## What JanusGuard does

- Reads an APK file from a local path **as raw bytes**.
- Parses the file as a **ZIP archive** using the Python standard library
  (`zipfile`), without executing any contained code.
- Inspects metadata: `META-INF/` entries, the optional APK Signing Block,
  file magic bytes at offset 0, and the embedded ZIP End-of-Central-Directory
  record.
- Classifies the APK against rules tied to the Janus vulnerability
  (CVE-2017-13156) and produces a Markdown, HTML, or JSON report with
  severity, rationale, and mitigation guidance.

## What JanusGuard explicitly does NOT do

- **No installation.** The tool never invokes `adb install`, `pm install`, or
  any package manager. It never connects to a device, emulator, or ADB
  daemon.
- **No execution of APK contents.** DEX bytecode, native libraries, and
  resources are never loaded, interpreted, or run. The DEX header is read as
  bytes; nothing inside the DEX is parsed beyond the fixed-offset magic and
  declared file size.
- **No modification of APKs.** JanusGuard opens files read-only. It does not
  write to, repackage, re-sign, or alter any APK.
- **No network activity.** The tool performs no outbound connections. It does
  not call home, fetch rule updates, or upload reports.
- **No exploitation.** The repository does not contain a working Janus
  exploit, an APK-prepending utility, or any code that would help an attacker
  craft a malicious package. The synthetic "janus-style" sample is a
  deliberately invalid ZIP-with-DEX-prefix shape used only to verify that the
  detector fires; it is not installable and has no payload.
- **No cryptographic verification.** JanusGuard does **not** verify that an
  APK signature is mathematically valid. It detects the **presence** of
  signing-scheme markers (v1 metadata files, v2/v3 block IDs in the APK
  Signing Block) to reason about which schemes are claimed. Real signature
  verification belongs to `apksigner` and the Android platform.

## Why this scoping matters

Janus (CVE-2017-13156) is a real, historically significant Android
vulnerability. It is also a topic where careless implementation work could
easily cross the line from "defensive analyzer" into "vulnerability research
tool". We have intentionally kept JanusGuard on the defensive side:

- All findings are framed as **risk indicators**, not exploitation instructions.
- The HIGH/CRITICAL escalation logic exists to highlight that an APK *should
  be reviewed manually*; it never claims that an APK *is* malicious.
- The synthetic samples are non-installable and serve only as test fixtures
  for the detector.

## Sample APKs

The repository ships five synthetic APKs in `samples/`. They are generated by
`samples/generate_samples.py` and are byte-shaped to exercise specific
detection paths:

| Sample                  | Purpose                                              |
| ----------------------- | ---------------------------------------------------- |
| `sample_modern.apk`     | v2-only, well-formed ZIP. Expect verdict `OK`.       |
| `sample_v1_v2.apk`      | v1 + v2 + v3 schemes present. Expect `LOW`.          |
| `sample_v1_only.apk`    | v1-only (legacy). Expect `MEDIUM`.                   |
| `sample_unsigned.apk`   | No signing metadata at all. Expect `MEDIUM`.         |
| `sample_janus_style.apk`| DEX magic prepended to a valid ZIP. Expect `CRITICAL`.|

None of these files are installable on Android. They contain no valid
cryptographic signatures, no AndroidManifest.xml binary resources, and no
executable DEX bytecode — only the minimal byte structures needed to
exercise our detection rules.

For testing against **real** APKs, see `README.md` § *Testing with real APKs*.
We recommend F-Droid releases, which are openly published and intended to be
inspected.

## If you find a bug

Please open a GitHub issue. Do not include real, signed APKs from third
parties as attachments; describe the file shape or provide a synthetic
reproducer instead.
